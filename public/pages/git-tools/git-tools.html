Git

Git is a distributed version control system used to track changes in a project.

Git makes it possible to save different versions of code, view previous changes and work with branches.

Basic Git Commands

  • git init - Initializes a new Git repository.
  • git status - Shows the current state of the working directory and staging area.
  • git add . - Stages changes in the current directory and its subdirectories.
  • git commit -m "message" - Creates a commit with the staged changes.
  • git log - Shows the commit history.
  • git diff - Shows unstaged changes.

GitHub

GitHub is a platform for hosting Git repositories online.

Git is used for version control, while GitHub makes it possible to store repositories remotely, share code and collaborate with others.

Working with Remote Repositories

  • git clone URL - Creates a local copy of a remote repository.
  • git remote -v - Shows the configured remote repositories.
  • git push - Uploads local commits to a remote repository.
  • git pull - Fetches and integrates changes from a remote repository into the current branch.
  • git fetch - Downloads remote changes without automatically merging them into the current branch.

Branches and Pull Requests

Branches make it possible to work on changes without directly modifying the main branch.

On GitHub, a pull request can be created to propose changes, review code and merge changes into another branch.

Clean Code

Clean Code is about writing code that is easy to read, understand and maintain.

Following Clean Code principles makes it easier to work with code and make changes in the future.

Clean Code Principles

  • Meaningful names - Use descriptive names for variables and functions.
  • Small functions - Keep functions focused on a single responsibility.
  • Avoid repetition - Avoid duplicating the same code unnecessarily.
  • Consistent formatting - Use consistent indentation and formatting to improve readability.

Linting

Linting is the process of analyzing source code to identify potential errors and code quality issues.

A linter is a tool that checks code against a set of predefined rules without executing the program.

ESLint

ESLint is a linting tool for JavaScript.

It can help developers identify potential problems, unused variables and inconsistencies in code style.

Using a linter can help improve code quality and maintain consistency across a project.

Nodemon

Nodemon is a development tool that automatically restarts a Node.js application when changes are detected in watched files.

This makes development easier because the server does not have to be restarted manually after every change.

Installing Nodemon

npm install --save-dev nodemon

The --save-dev flag installs Nodemon as a development dependency.

Running Nodemon

npx nodemon app.js

This starts the application using Nodemon.

npx nodemon --ext js,html,css app.js

The --ext option specifies which file extensions Nodemon should watch. In this example, changes to JavaScript, HTML and CSS files can trigger a restart.

Postman

Postman is a tool used to send HTTP requests and test APIs.

It makes it possible to test endpoints without creating a frontend application.

Testing API Endpoints

Postman supports different HTTP methods, including GET, POST, PUT, PATCH and DELETE.

For example, an API with an animals resource can be tested using these requests:

  • GET /animals - Retrieves all animals.
  • GET /animals/1 - Retrieves an animal by its ID.
  • POST /animals - Creates a new animal.
  • PUT /animals/1 - Replaces an existing animal.
  • PATCH /animals/1 - Partially updates an existing animal.
  • DELETE /animals/1 - Deletes an animal.

Request Body and Responses

When sending a POST or PATCH request, JSON data can be included in the request body.

{
    "name": "Parrot",
    "age": 34
}

Postman displays the server's response, including the status code and response body.

This can be used to check whether an endpoint behaves as expected.

Deployment

Deployment is the process of making an application available outside the local development environment.

During development, a Node.js application can run locally on localhost. After deployment, the application can be accessed through a public URL.

Deploying a Node.js Application

A Node.js application can be deployed to a hosting platform that supports its runtime and configuration.

In the course, we worked with deployment using Vercel.

Important Considerations

  • The application must have the correct configuration for the hosting environment.
  • Dependencies must be declared in package.json.
  • Environment variables can be used for configuration that differs between development and production.
  • Static files must be accessible through the correct paths.

Local Development vs. Production

During local development, tools such as Nodemon can automatically restart the application when files change.

In production, the application runs in a deployed environment where users can access it without running the project on their own computers.
